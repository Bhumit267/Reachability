# 🎬 CVE Commander — Demo Script (3 to 5 Minutes)

> **Theme:** How FalkorDB gives AI agents deterministic structural context and episodic memory to autonomously mitigate critical security incidents without hallucinating.

---

## ⏱️ Timeline & Script Beats

### [0:00 - 0:45] Beat 1: The Context & Memory Problem
- **Action:** Open terminal showing FalkorDB running and launch Streamlit dashboard:
  ```bash
  streamlit run app/streamlit_app.py
  ```
- **Spoken Words:**
  > "Hi everyone. When a critical CVE drops on production infrastructure at 2 AM, security engineers can't afford hallucinations or guess-work.
  > Today, LLM agents usually rely on vector embeddings. But vector search only finds keyword similarity—it has no understanding of network hops, IAM permissions, or code hierarchies. Worse, agents suffer from episodic amnesia: they repeat the exact same broken runbook steps that caused an outage last week.
  > We built **CVE Commander**, powered by **FalkorDB**, to give agents two essential superpowers: deterministic structural context and graph-native episodic memory."

---

### [0:45 - 1:30] Beat 2: Incident Detection & Trigger
- **Action:** Point to the left column: **Incident Control**.
  - Select Service: `payments-api`
  - Select Vulnerability: `CVE-2024-3094` (Critical CVSS 10.0 backdoor)
  - Click **🚀 Run Incident**.
- **Spoken Words:**
  > "Let's see this in action. A critical vulnerability—CVE-2024-3094—has been detected on `payments-api`.
  > We trigger the incident run. Under the hood, an autonomous orchestrator initiates an Incident node with status 'open' in FalkorDB and dispatches three specialized agents."

---

### [1:30 - 2:30] Beat 3: Blast Radius & Code Impact Analysis
- **Action:** Point to Right Column: **Graph Evidence & Memory**.
  - Expand **Path 1** and **Path 2**.
  - Expand **Agent Reasoning Summaries**.
- **Spoken Words:**
  > "Notice what happened:
  > First, our **Security Agent** traversed the graph from `payments-api` across its hosting assets to our Crown Jewels. It found that the affected Kubernetes node has a direct path to both the `CustomerPIIStore` and `PaymentLedger` databases. If an agent tries to answer without a verifiable Cypher path, our engine rejects it.
  > Second, the **Code Impact Agent** mapped the service to its Git repository, identifying `src/payment_handler.py` and the `process_payment` function, along with service owner Alice Smith and the on-call engineer. Every claim is grounded in graph reality."

---

### [2:30 - 3:45] Beat 4: Memory Recall & The Runbook Step Switch
- **Action:** Point to Middle Column: **Incident Timeline** and the Amber **Memory Influence Callout** on the right.
  - Highlight Action 4: `SWITCH_RUNBOOK_STEP`.
  - Expand the Memory Callout showing episode `mem-ep-payments-01`.
- **Spoken Words:**
  > "Here is the key innovation in Track 02: **Agent Memory**.
  > Normally, the standard runbook instructs the agent to apply a strict WAF ingress drop rule.
  > But before taking action, our Commander queried `recall_for_decision` in FalkorDB. The graph traversed past incident episodes and warned the agent: in past episode `mem-ep-payments-01`, dropping ingress traffic broke merchant webhooks and caused an outage.
  > Because of this graph memory, the Commander dynamically switched runbook steps to `VPC Security Group Egress Lockdown`.
  > Look at the chronological timeline:
  > 1. Host `k8s-node-payments-prod-01` isolated.
  > 2. Mitigation ticket opened for Alice Smith.
  > 3. PagerDuty alert sent to Payments On-Call.
  > 4. Runbook diverted with full graph justification.
  > 5. Incident closed with status 'CONTAINED', and the new lesson learned was saved back to FalkorDB."

---

### [3:45 - 4:30] Beat 5: Explanation Layer & Wrap-up
- **Action:** Click on any action in the timeline to reveal the exact arrow path:
  `payments-api → RUNS_ON → k8s-node-payments-prod-01 → REACHES → CustomerPIIStore`
- **Spoken Words:**
  > "Every decision has a complete audit trail. Any engineer or auditor can inspect the exact graph path that justified every action.
  > FalkorDB transformed an unpredictable LLM into a reliable, accountable incident commander with long-term memory.
  > Thank you!"
